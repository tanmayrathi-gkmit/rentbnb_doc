    Role-Based Permission Matrix¶

    This matrix defines what each role can do across all modules in the system. All permissions are tenant-scoped unless explicitly marked as "Global" (system-wide).

    Legend¶

    • Yes - Full access to this operation
    • Own - Can only access their own resources
    • Tenant - Can access all resources within their tenant
    • No - No access to this operation
    • Global - System-wide access across all tenants

    Key Permission Principles¶

    1. Tenant Isolation: All operational data (properties, bookings, payments, reviews, messages) is strictly tenant-scoped
    2. SUPER_ADMIN Limited Scope: SUPER_ADMIN has global access ONLY to:
    3. Tenants: Full CRUD operations across all tenants
    4. Users: View, create, update, delete users across all tenants
    5. Amenities: Global amenity catalog management
    6. Platform Dashboard: System-wide analytics and metrics
    7. SUPER_ADMIN Restrictions: SUPER_ADMIN does NOT have access to:
    8. Properties, Bookings, Payments, Reviews, or Messages (all tenant-scoped)
    9. These require tenant membership and appropriate role (TENANT_ADMIN, MANAGER, or GUEST)
    10. TENANT_ADMIN Privileges: Full control within their tenant, including user management and all operational features
    11. MANAGER Privileges: Can manage properties, amenities, bookings, and payments within their tenant
    12. GUEST Privileges: Can create bookings, make payments, and write reviews for completed bookings
    13. Self-Service: All roles can manage their own profile and view their own bookings/payments
    14. Review Restrictions: Reviews can only be created by GUEST users for properties with completed bookings
    15. Message Privacy: Users can only view conversations they are part of (except TENANT_ADMIN who can view all tenant messages)
